## Explicit local backup utility
The macOS-only tools/local_backup.py takes three user-selected existing paths: application bundle, data directory and private backup parent. Quit the application first. The tool refuses overlapping source/destination directories, symlinks in the selected paths, special files, hard-linked files and symlink targets outside the selected source. It uses ditto to preserve macOS file metadata, compares SHA-256 file manifests and symlink targets before and after copying, and writes a local receipt only after verification. It creates a new private backup folder and never removes or replaces the original application/data. It rejects a destination parent accessible to group/other users. The receipt contains relative file paths and digests, so it too is private. Backups may contain credentials; keep them on an encrypted local disk, never upload them. Use Finder or Time Machine for user-approved manual restoration; no automatic restore command. A live writer can defeat snapshot consistency; the application must be closed. Metadata/ACL preservation relies on ditto, not on the content manifest. This is a generic utility, not an integration into HGhub. Test fixtures use synthetic directories only.

Backup safety follow-up: directory traversal errors fail the operation, and a complete fsynced receipt is renamed to its final verified name only on success. A partial receipt is never labeled verified. Added two regression cases. The new push may supersede the currently running lab CI; check the latest run before declaring acceptance.

## Independent network diagnostic
tools/network_probe.py performs a single HEAD request to an explicitly selected, authorized HTTP(S) health endpoint with the normal curl network environment. It preserves TLS verification, disables curl config-file loading, does not follow redirects, does not change DNS, proxies or routes, and does not read a response body. It reports only error category, HTTP status and elapsed milliseconds (no URL, headers, tokens or raw error output). It distinguishes proxy DNS, host DNS, connection failure, timeout, TLS handshake, certificate rejection, access denial, rate limiting, server errors and redirects. A HEAD result does not establish GET or application protocol compatibility. Local fixture tests use only a disposable loopback HTTP server. This is a general diagnostic tool, not a content-service adapter or integration into the application.
