# HGhub maintenance candidate v1.2.9

Independent candidate branch; preserve the user-tested 50b534f baseline. Native updater accepts only fixed GitHub channels and a public key pinned at build time. No key means disabled installation. No remote code hot-loading, automatic installation, automatic publishing or scheduled workflow. Startup check is once per app launch. Separate stable and beta manifest tags avoid iOS/macOS confusion. 

## Signing bootstrap (owner action)
Use the official Tauri signer to generate a long-lived signing key locally. Store the private key in a protected GitHub Actions environment as TAURI_SIGNING_PRIVATE_KEY (and password as TAURI_SIGNING_PRIVATE_KEY_PASSWORD); store its matching public key as repository variable HGHUB_UPDATER_PUBLIC_KEY. Never paste a private key in issues, commits, chat or logs. The GitHub connector cannot set secrets. Only after key setup and explicit release approval can a separately reviewed signing job generate a versioned universal updater archive and signed manifest. Keep the same public key across releases. Never automatically trust a key from the manifest. See https://v2.tauri.app/plugin/updater/.

Channel manifest endpoints: fixed release tags macos-stable / macos-beta, asset latest.json. Each manifest platform macos-universal must point at a versioned repository .app.tar.gz and include its Tauri signature. Channel manifests must be published last; leave existing manifests unchanged on failed tests. The candidate workflow deliberately never publishes. No formal signed channel exists yet. Native install only accepts newer versions; rollback remains a manual, separately reviewed recovery operation. User data and WARP device files remain outside the replaced app bundle. Native updater test installation, download progress, backup and rollback, launch health, trusted-source refresh, and on-demand upstream metadata tracking remain subsequent work. 

Regression checks: fixed channel allowlist, fixed asset origin and file type, existing Rust/frontend tests, Universal architecture and DMG integrity. Cargo resolves the pinned dependency in CI and uploads lockfile for review. Do not merge until reviewed and locked.
